# Orchestration 0.4.2 — STABLE

version: 0.4.2
status: STABLE
released_at: 2026-11-08
baseline: /Orchestration/protocol/releases/v0.4.1/PROTOCOL.md

## Назначение

Точечное изменение 0.4.1: перезапись файлов Library по-прежнему запрещена, но удаление разрешено как отдельное действие. Папки остаются предпочтительным способом фиксации простых событий. Все остальные правила 0.4.1, включая простую миграцию с 0.3.0, сохраняются, если явно не изменены ниже.

## 1. Файлы: создание, удаление, запрет перезаписи

1. Запрещено изменять содержимое уже существующего файла на месте, использовать `overwrite=true`, обновлять его версию либо подменять его скрытой операцией. Если файл существует и удаления не разрешали, создавать новый уникальный путь или остановиться.
2. **Удаление разрешено.** Файл или папку можно удалить в границах текущего проекта и конкретной задачи, когда это прямо вытекает из просьбы пользователя либо отдельно согласовано. Сам факт технической доступности удаления не является разрешением уничтожать данные. Не удалять чужие проекты, результаты или исторические релизы без их отдельного разрешения.
3. Удаление существующего файла и последующее создание нового файла с тем же именем — **две отдельные операции**, не перезапись. Для замены указателя или другого рабочего документа по тому же пути требуется явное разрешение на удаление прежнего объекта. Не проводить такую последовательность скрыто ради обхода запрета на перезапись.
4. Перед удалением определить точный объект. Для непустой папки рекурсивное удаление допустимо только при явно охваченном содержимом. После удаления проверить отсутствие объекта в Library; после создания — его наличие и содержимое. При частичной ошибке сообщить о ней и исправлять адресно, без бесконечных тестов и многократных аудитов.
5. Архивирование ветки по-прежнему означает **перемещение папки**, а не удаление. Предпочтение папок вместо файлов не меняется. Удаление не объявляется обязательным этапом миграции или закрытия ветки.

## 2. Production и CURRENT.md

`/Orchestration/protocol/CURRENT.md` снова является основным production-указателем и остаётся совместимым со старыми инструкциями запуска. Для утверждённого нового релиза:

1. Создать новый отдельный неизменяемый файл релиза и проверить его через Library read.
2. По разрешению на замену production-указателя удалить **только** прежний `CURRENT.md` и проверить отсутствие.
3. Создать **новый** `CURRENT.md` с точной версией и путём STABLE-релиза, прочитать его обратно и проверить согласованность.
4. Для совместимости с агентами 0.4.1, уже использующими `protocol/production/`, создать папку-маркер утверждённого релиза и проверить её. Старые маркеры и выпуски сохранять.

Не использовать операцию перезаписи, редактирование того же файла и автоматическую зачистку старых версий. Если новый CURRENT не удалось создать, не объявлять переход завершённым: восстановить корректный указатель отдельной операцией создания после установления причины, сохраняя проверенный STABLE-релиз. Если CURRENT и production-маркеры противоречат друг другу, не скрывать расхождение; проверить наличие точного релиза и сообщить о незавершённом переходе. После успешного обновления CURRENT менять внешние инструкции запуска только ради обнаружения версии не требуется.

## 3. Простая миграция проекта 0.3.0/0.4.0/0.4.1 → 0.4.2

Миграция любого действующего проекта требует отдельного прямого разрешения именно для него. Прочитать минимальный существующий контекст, создать событие-папку `Status/<unique>--upgrade-to-042/` и после фактической проверки — папку `Protocol/adopted/v0.4.2/`. Старые файлы не перезаписывать. Никакой полной конвертации истории, удаления старой структуры или серии аудитов не требуется. Допускается отдельное удаление явно ненужных объектов, но миграция сама по себе не даёт на него разрешения.

Локальная закреплённая версия конкретного проекта определяется по подтверждённой папке принятия протокола согласно 0.4.1, при её отсутствии — по прежнему INIT.md. Публикация 0.4.2 не переводит остальные проекты автоматически.

## 4. Проверка

Достаточно реального readback созданного релиза и рабочего production-указателя, проверки операции удаления прежнего указателя и видимости маркера. Никаких дополнительных обязательных тестовых проектов, повторных аудитов и служебных журналов не вводится.
